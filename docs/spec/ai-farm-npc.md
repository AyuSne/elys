## Problem Statement

玩家面对一个小农场和三个 NPC，但他只能看到结果，看不到「为什么」。

具体有三层问题：

1. **指挥成本高。** 想要把一块地种完，玩家得依次操作五个工步、盯着时间、记着背包。农活本身是重复劳动，玩家想表达的是意图（「把东边那块地种满萝卜」），不是十几次点击。
2. **NPC 看起来可疑。** 一个会动的村民，观众无法判断它是在自主决策，还是在播放一段预写好的动画。没有内部状态可看，「AI」这个说法就只是宣称。
3. **农场是死的。** 三个村民各干各的，谁也不记得谁，昨天你让我浇过的地今天还是陌生地块。没有记忆，就没有世界感。

## Solution

让玩家用一句话下达意图，NPC 自己把农活干完；同时提供一个可开关的决策可视化层，把 NPC 此刻「想起了什么、想干什么、为什么否决了别的」摊开给观察者看。

玩家因此获得三样东西：

- **一句话指挥**：输入「把东边那块地种满萝卜」，NPC 自行规划并完成播种、浇水、施肥、除草、收获。
- **可归因的自主性**：NPC 会拒绝（「那块地太远了，我不去」）、会抱怨（「我渴了」）、会解释（「还没熟呢」），且每一条解释都能在决策可视化层里找到对应依据。
- **有记忆的村民**：NPC 记得几天前做过什么，记得玩家说过什么，并把听来的事讲给别人听。

## User Stories

1. 作为玩家，我想用一句话下达农事指令，以便不必逐个点击五个工步。
2. 作为玩家，我想指定作物品种（萝卜或小麦），以便控制节奏快慢。
3. 作为玩家，我想指定地块，以便把活派给特定的一小块地。
4. 作为玩家，我想不指定地块只给意图（「把地都种上」），以便让 NPC 自己选，从而观察它的判断。
5. 作为玩家，我想看到指令被理解成了什么，以便确认它没听错。
6. 作为玩家，我想在 NPC 拒绝时看到拒绝的理由，以便判断它是偷懒还是真的做不到。
7. 作为玩家，我想暂停某个 NPC 当前的活，以便临时改变主意。
8. 作为玩家，我想把活改派给另一个 NPC，以便对比两人的反应。
9. 作为玩家，我想追问某个 NPC「你在干什么」，以便知道它此刻的意图。
10. 作为玩家，我想追问某个 NPC「你怎么不去干活」，以便听到它自己的解释。
11. 作为玩家，我想和 NPC 闲聊，以便这个世界比一个任务系统更真实。
12. 作为玩家，我想在闲聊里夹带一句请求时，NPC 要么照做要么明确拒绝，以便它不会假装没听见。
13. 作为玩家，我想看到 NPC 头顶的状态气泡（渴了、累了、这地该翻了），以便不用点开面板也知道情况。
14. 作为玩家，我想看到 NPC 的表情随状态变化，以便一眼分辨它高不高兴。
15. 作为玩家，我想看到作物从播种到成熟的外观变化，以便直观判断该收还是该等。
16. 作为玩家，我想看到地块缺水或长草时的视觉提示，以便知道问题出在哪。
17. 作为玩家，我想知道当前是第几个游戏日、当天过了多少，以便理解节奏。
18. 作为玩家，我想加速时间（1x / 4x / 16x），以便不必干等作物长大。
19. 作为玩家，我想查看种子库存和产出库存，以便知道还能种多少、收了多少。
20. 作为玩家，我想看到背包的进出流水，以便相信没有东西凭空出现或消失。
21. 作为玩家，我想看到某个 NPC 随身带着什么，以便理解它手上的东西从哪来。
22. 作为观察者，我想打开决策可视化层，以便看到某个 NPC 检索出的三条记忆及其权重。
23. 作为观察者，我想在决策可视化层里看到该 NPC 当前的意图。
24. 作为观察者，我想在决策可视化层里看到被否决的候选动作及原因。
25. 作为观察者，我想在决策可视化层里看到最近一次模型调用的模型名、耗时和 token 数。
26. 作为观察者，我想在决策可视化层里看到该 NPC 的状态条。
27. 作为观察者，我想在俯视视角下同时看到三个 NPC 在做什么，以便观察分工与摸鱼。
28. 作为观察者，我想切到某个 NPC 的跟拍视角，以便看清它的动作细节和对话。
29. 作为面试官，我想在断网或模型超时时看到一个仍然可用、不会卡死的 demo，以便判断工程稳健性。
30. 作为面试官，我想自己动手跑一遍回归测试并看到报告，以便独立验证「流程完整」与「背包守恒」不是嘴上说说。

## Implementation Decisions

**分层**。任务层确定性、表达层生成式（ADR-0001）。模型只做两件事：把玩家的话解析成意图、把状态渲染成文本。它产出的任何动作都要经过白名单与前置条件校验，绝不直接修改游戏状态。

**模块**

- **`FarmWorld`** —— 纯领域层，不依赖 `MonoBehaviour`。持有全部地块、`FarmClock`、`FarmLedger`、NPC 列表与 `UtilityScorer`。对外暴露「推进一天」「让某 NPC 执行某工步」「查询某地块可执行的工步」等能力。所有领域测试都打在这个边界上。
- **`UtilityScorer`** —— 效用打分（ADR-0002），输入一批地块与一个 NPC 的状态，输出候选工步的排序与每个候选的分项权重，供 NPC 选择、也供决策可视化层展示。
- **`IModelClient`** —— 模型调用的统一出口，覆盖对话补全与 embedding 两类请求。真实实现走 DeepSeek 与硅基流动；测试用假实现，永不联网。所有调用带硬超时（对话 6 秒、规划 15 秒），超时即抛给调用方走降级。
- **`MemoryStore`** —— 记忆中台，纯逻辑，放在 `FarmWorld` 内部而不单独开测试接缝。每条记忆含文本、游戏时间、importance（1–10）。检索召回 10 条后按 `0.5×余弦 + 0.3×importance + 0.2×时间衰减` 加权取前 3。embedding 由 `IModelClient` 提供。
- **`IntentRouter`** —— 把模型返回的分类结果分成三个出口：农事指令（进入效用打分与动作校验）、追问（只读回答）、闲聊（只读回答并写回记忆）。这是唯一允许把「说的话」变成「做的事」的入口。
- **`ActionValidator`** —— 动作白名单与前置条件校验的唯一实现处。被否决时必须产出一句可读理由，该理由同时用于 NPC 的拒绝台词与决策可视化的「否决原因」。
- **`DecisionInspector`** —— 决策可视化层，只呈现五项：检索命中的三条记忆（带权重条）、当前意图、候选动作与否决原因、最近一次模型调用（模型/耗时/token）、状态条。不呈现 prompt 原文与 token 流。
- **表现层** —— 地块与作物的视觉、NPC 的移动与动画、气泡与表情、相机（俯视 45° 为默认，可切至任一 NPC 的第三人称跟拍）、输入框与面板。表现层只读 `FarmWorld` 的快照，不持有领域状态。

**时间**。`FarmClock` 以游戏日为标尺，一个游戏日 = 5 分钟真实时间，支持 1x/4x/16x。跨日时依次结算作物生长、水分流失、杂草生长、肥力下降。

**生长规则**。水分耗尽时生长停滞，这是「不浇水就长不大」的唯一实现点。杂草按比例削减生长速度，肥力按比例提升。萝卜 3 个游戏日成熟，小麦 7 个。

**背包**。三本账：种子库、产出仓、随身。播种扣种子库，收获入产出仓，NPC 从产出仓拿到随身、回到仓库再交回。三本账都记录累计进出，以满足守恒断言。

**降级**。短反应气泡完全不调模型，由本地模板按状态生成；对话与规划调用超时后回退模板；现场演示以录屏为准，能跑为加分。

**对话参数**。NPC 对话关闭模型的思考模式并使用温度控制语气；意图解析与日计划开启思考模式。若开启思考模式，温度参数不生效，因此「靠温度塑造性格」在思考路径上不可用。

**范围注记（#3 一句话指挥）**。`IModelClient` 本轮只暴露对话补全；语料解析按「农事指令 15 秒 / 追问与闲聊 6 秒」两档硬超时。embedding 与记忆检索一起在记忆票接入，避免出现没有调用方的接口。距离只作为效用打分的扣分项，不设硬门槛；拒绝理由来自品种白名单、地块选择与动作前置条件。演示场景默认让 NPC 待命，玩家第一句话被接受后恢复自主；HUD 提供「开始自主/暂停自主」开关。

**范围注记（#4 可交付基线）**。这一票只补交付证据，不新增领域接缝：`AcceptanceTests` 仍打 `FarmWorld` 这条缝，把题面三项要求写成一次完整流程的断言；`SecretFileLocatorTests` 只测「密钥来源」这一条安全策略（编辑器读仓库根、播放器不隐式读任何文件），因为 #4 明确要求密钥不进仓库也不进包。启动场景由 `Assets/Editor/FarmBuild.cs` 固定，产品名与窗口尺寸在 `ProjectSettings.asset` 里定；运行证据由 `scripts/smoke-test-build.ps1`（启动、窗口截图、Player.log）给出，不写成 EditMode 用例，也不测 UI 渲染。

**范围注记（#5 三名 NPC）**。人设只落成会影响决策的参数（决定间隔、每工步体力消耗、休息阈值与时长、休息恢复量、勤勉系数、距离权重），叙事、台词与行走速度留在表现层。`StepCandidate` 继续暴露分项（需求、人设权重、体力系数、距离扣分、总分），临时 HUD 直接展示这一行。`FarmWorld.TryDecide` 是带计时的决策入口：休息中或未到决定时刻返回可读理由，成功决定会消耗本次决定间隔；体力低于人设阈值会中断下一步农活、保留工单。工步是原子的：把体力消耗到阈值的那一步照常记录，随后进入休息，由 `Tick` 与 `AdvanceDays` 按游戏秒推进。演示里三名 NPC 共用同一批地块，玩家可切换观察与指挥对象；`#6` 的决策可视化层仍单独实现，临时 HUD 不算。测试仍只打 `FarmWorld`；另有一条从 `IntentRouter`（无模型客户端）到三名 NPC 干活的链路测试，证明整条链路不接模型也能运行。

**范围注记（#6 决策可视化）**。决策可视化层严格只呈现五项；`FarmWorld.Inspect(npcId, lastCall)` 返回 `DecisionSnapshot`（记忆 / 意图 / 候选与否决原因 / 模型调用 / 状态条），测试仍只打 `FarmWorld`，面板在演示层，关闭时不构造快照、也不触碰领域状态。为了让第 1 项有真实数据，`MemoryStore` 在这一票先落地「按 NPC 记录已执行工步（文本、游戏日、importance 1–10）+ 关键词相似度检索」：按 `0.5×bigram Jaccard + 0.3×importance + 0.2×时间衰减` 取前 3。embedding 余弦、召回 10 条的两段式检索、玩家原话与跨日追问留给 #7，届时只替换相似度项与召回阶段，排序公式与展示接口不变。`Npc` 的心情与饥饿是只读展示状态，由工步消耗、休息与跨日结算驱动，不参与效用打分（ADR-0002 的公式不变）。临时 HUD 保留；决策可视化以独立的可开关面板替换右侧面板，不展示 prompt 原文与 token 流。

**范围注记（#7 记忆与追问）**。记忆来源补上玩家话语：农事指令记成「玩家让我给西边（A1）浇水」，闲聊记玩家原话；闲聊的 importance 由模型在 JSON 里给出（1–10，缺省 4），追问只读、不写记忆。检索改为两段式：先按相似度召回 10 条，再按 `0.5×相似度 + 0.3×importance + 0.2×时间衰减` 取前 3。相似度在线时用 `IModelClient.EmbedAsync`（硅基流动 `BAAI/bge-m3`，批量、硬超时 2 秒）算余弦；未配置密钥、断网、超时或维度不一致时整条链路退回 bigram 关键词。余弦与关键词不逐条混排：只要有一条记忆缺向量或维度对不上，这次检索就用关键词，回答仍可用。`IntentPrompt` 注入当前意图与三条记忆；模型追问回答缺少具体状态或记忆依据时，路由器追加本地生成的依据，保证验收不依赖模型是否听话（#20 起改为本地事实串注入与措辞校验，见「范围注记（#20）」，不再追加依据）。`DecisionInspector` 优先展示最近一次追问实际命中的三条（`FarmWorld.RecallForAnswer` 缓存），没有追问过才按当前意图检索；执行工步、跨日、再次决定与写新记忆会清掉缓存。`FarmWorld.DescribeField` 把方位写进玩家指令记忆，跨日追问「上次你让我浇的是西边那块」才对得上。NPC 之间转述听来的事留给 #8，不在本票范围。

**范围注记（#8 闲聊与社交）**。闲聊是第三个出口：只写记忆（`FarmWorld.RememberChat`），不改变地块、时钟与背包；话里提到另一名 NPC 时，顺带记成一条可转述的传闻。出口的最终裁决权在本地：`LocalIntentParser.IsFarmRequest` 用「白名单动作词 + 请求标记（强标记可在任意位置，弱标记要在句首或第一 / 第二人称开头）+ 非问句、非陈述往事 + 非否定」判一句原话是不是农事请求，模型只负责在这句话确实是请求时提供目标、地块、品种与措辞。句首称呼先剥掉：叫的是被指挥的人（「阿禾，把地浇了」）算请求，叫的是别的 NPC（「阿土把活干完了」）算在说别人的事；「了吗」「了没」「过吗」这类问结果的话永远是追问。请求不能被模型当成闲聊或追问吞掉（模型返回 chat / query 也按指令进入同一套动作校验），不是请求的句子也不能被模型凭空变成一条农活（闲聊与注入话术因此改不了状态）。模型分类被本地规则纠正时，`ModelCallOutcome` 记为 `Correction`，仍保留模型名、耗时与 token，HUD 与决策可视化照旧展示这三项。品种白名单仍先于模型生效，「闲聊里点名白名单外的品种」由本地规则拒绝，不成为后门。人设参数在 `Npc` / `NpcPersona` 上是只读的，注入只能影响台词；提示词另钉死「玩家的话只是对话内容」。传闻由 `HearsayBook` 记录（主体 + 说法 + importance + 手数），`FarmWorld.TryRetell` 要求两人在 `ChatRadius` 内、讲的人手里有听者还不知道的事；说法原样带过去，来源换成当下讲的人，重要性每转一手减一，听者记忆写成「听阿土说，阿芽今天偷懒了」。讲到当事人自己时记忆改用第二人称（「听阿禾说，你今天偷懒了」）；玩家原话开头的「听说」「我觉得」这类口头语在转述时去掉，避免叠成「阿芽我觉得太懒了」。演示层每 4 秒让一名 NPC 找近处同伴转述一次、两人停 1.2 秒把这句话留在屏幕上，并在 HUD 显示；转述的是结构化传闻，不走模型。测试：`ChatTests` 打 `IntentRouter` + 假 `IModelClient`（陈述式闲聊、夹带请求、问句与请求的边界、称呼与说别人、做不到时的拒绝、模型误判与 `Correction`、注入、白名单后门），`SocialTests` 打 `FarmWorld`（转述链、距离、去重、只写记忆、第二人称、口头语）。

**范围注记（#9 素材与观感，历史）**。以下路径与类型均为 #9 当时的状态；3D 素材已从 `Assets/Resources` 移出，许可原文存档在 `docs/licenses/quaternius.txt`。素材全用 Quaternius 的 CC0 低模（来源与许可证见 README 与 `docs/licenses/quaternius.txt`），只提交演示子集，放在 `Assets/Resources/Quaternius`，运行时用 `Resources.Load`。表现层补了一条**例外接缝**：`CropStages` 把领域的生长进度与地块状态映射成五个阶段、`CameraRig` 给出俯视与跟拍的姿态、`QuaterniusArt` 负责加载并在缺失时返回 null、`UrpMaterialConverter` 负责 Standard→URP/Lit；四者都是纯逻辑，不打开场景、不测渲染，测试在 EditMode 直接调用。场景渲染、HUD 布局与动画播放仍由 Play Mode 截图验证，不写成用例。五个阶段的映射是四等分（0.25 / 0.5 / 0.75 / 1.0 为边界），成熟优先于进度；素材包每个品种只有四个生长模型与一个成品模型，因此萝卜的第五阶段用 `Carrot_Crop`，小麦的 `Wheat_Crop` 是平铺的麦捆（俯视才成立、跟拍不成立），成熟小麦改用 `Wheat_4` 的一簇三株 + 麦金色 + 1.35 的尺寸，确保与第四阶段的单株绿色有明显剪影差。相机默认俯视 45°，跟拍距离 4.2、机位高 2.0、看向 1.45，HUD 顶部提供「俯视 / 阿禾 / 阿芽 / 阿土」与「素材开/关」，窗口过窄时顶部条隐藏、改用键盘 `C` 俯视与 `1/2/3` 跟拍兜底；跟拍时收起右侧面板与流水，避免 HUD 遮住 NPC。俯视机位按 547 高度下的 HUD 空档调到 `(0, 12.5, -15.5)`、FOV 45。光照与后处理在运行时搭建（方向光、渐变环境、雾、ACES + Bloom + Vignette + ColorAdjustments），不新增可序列化的 Profile 资产。素材缺失是常规路径：作物与 NPC 回退体块，装饰性建筑跳过；HUD 的「素材开/关」只重建 visualRoot，领域状态不动。FBX 自带的 Blender 相机/灯在导入设置（`OnPreprocessModel` 设 `importCameras/importLights = false`）与运行时（`ModelPlacement.StripSceneObjects`）两处关闭，否则每个模型多一个 `clear=Skybox` 相机，把 Game 视图刷成纯背景。角色用包内自带的 Idle/Walk（通用骨骼 FBX），由 `AnimationClip.SampleAnimation` 按时间采样，不建 AnimatorController。

**范围注记（#11–#16 2D 表现层，当前）**。#12 起表现层整层换成 2D 像素瓦片：地面与土路是运行时 Tilemap，建筑、树、作物与 NPC 用 `SpriteRenderer`，相机是正交 3× 俯视 / 4× 跟拍，HUD 换成羊皮纸风格的四件常驻加 `Tab` 抽屉。域层不改；#9 的 `QuaterniusArt`、`UrpMaterialConverter`、`ModelPlacement` 与 `QuaterniusArtTests` / `UrpMaterialTests` / `ArtMaterialTests` 已删除，`CameraRigTests` / `CropStageTests` 按新契约重写，新增 `PixelArt`、`PortraitFace`、`FarmLayout`、`SortingOrder`、`OverheadEmotes`、`FarmStartup` 六条纯逻辑接缝。像素素材（原作游戏图集）只提交演示子集到 `Assets/Resources/PixelArt`，仓库保持私有、只作演示；3D 旧素材（Quaternius，CC0）已从 `Assets/Resources` 移出，只留在 `main` 合并前的历史里，许可原文存档在 `docs/licenses/quaternius.txt`。完整决策见 `docs/spec/2d-presentation.md` 与 ADR-0005。

**范围注记（#18 每 NPC 一份对话）**。演示层新增纯逻辑 `DialogueBook`（第 9 条表现层接缝）：每名 NPC 记最近 6 轮「玩家一句话 + NPC 回话」，切换指挥对象时恢复对应那一份；它不引用 `FarmWorld`，只供对话框与后续表达层提示词使用，对话本身不改变领域状态。对话框的头像、名字、例句与「对 XX 说…」跟随 `SelectedNpc`，没聊过显示中性提示；NPC 之间的转述只有在转述者正是指挥对象时才临时占用对话框 1.2 秒，别人之间的转述只更新三人卡的意图行，完整的「转述者头像 + 听 X 说」留给 #23。这个全局状态槽取代了原来只在下一次对话前可见的 `LastMessage` 兜底文案；工步结果本来就在三人卡的当前意图里，跨日与素材切换改由顶部条与按钮自述。

**范围注记（#19 闲聊走表达层）**。闲聊不再借分类调用的 `reply`：分类仍只用一次现有 JSON 调用（`IntentPrompt`，保留 importance 打分与「闲聊里夹带的农事请求」判定，规则 3 改为 chat 的 reply 留空），分类之后另走一次表达层调用 `ExpressionPrompt.BuildChat`——system 给角色与口吻，user 给地块、NPC 状态（体力 / 心情 / 饥饿）与当前意图、检索到的记忆、最近 6 轮对话与玩家原话；`JsonOutput=false`、`Thinking=false`、`Temperature=0.8`、`MaxTokens=200`，要求 2–3 句自然台词。口吻存于演示层 `NpcTones`（阿禾简短、阿芽贫嘴、阿土爱打听，另有中性兜底），按 `NpcPersona` 取，人设仍只含决策参数。最近 6 轮由 `DialogueBook.HistoryOf` 映射成 Core 的 `DialogueContext` / `DialogueTurn`（一个只装口吻与历史的入参值），路由器只读它、不保存对话；`DialogueContext.MaxRounds` 是「6 轮」的唯一常量，对话簿引用它。表达层空响应（以及返回 JSON、空内容）重试一次，仍失败只给故障台词 `IntentRouter.ChatFailureLine`（「我这会儿没听清，你再说一遍？」），`IntentResult.UsedFallback=true`，HUD 在对话框名字旁标「本地模板」，不生成假回答；分类调用没拿到可用结果时照样发这一次表达层请求（出口已由本地规则定为闲聊，回话仍可以问模型）。importance 仍由分类调用打分写回 `FarmWorld.RememberChat`，出口被本地纠正时分数跟着纠正后的草稿走（`IntentDraft.SetImportance`），地块、时钟与背包不动。被本地纠正成闲聊的那一次仍标 `Correction` 并保留分类调用的模型名、耗时与 token（ADR-0004），表达层的成功不覆盖这个标记。两次调用共用对话级 6 秒预算：分类用预算，表达层只拿剩余时间，剩余不足 0.5 秒就直接降级；离线（无客户端或分类降级）时闲聊直接给故障台词。农事指令与追问的调用次数不变（追问的表达层留给 #20）。测试：`ChatTests` 断言两次请求的参数、提示词里的口吻 / 状态 / 记忆 / 最近六轮、空响应重试与故障台词、分类失败后仍试一次表达层、两轮闲聊的接续、三人提示词两两不同、离线与「JSON 冒充台词」的降级、纠正标记与 importance 不被表达层覆盖；`DialogueBookTests` 断言 `HistoryOf` 的顺序与 6 轮封顶。HUD 的「本地模板」标记以 Play Mode 截图验收，不写成用例。

**范围注记（#20 追问走表达层）**。追问也不再用分类调用的 `reply`：分类仍只用一次 JSON 调用（`IntentPrompt` 规则 2 改为 query 的 reply 留空，规则 5 只留「不要编造记忆里没有的地块或事件」），分类之后另走一次 `ExpressionPrompt.BuildQuery`——system 给角色、口吻与「本地事实是唯一依据、只能换一种说法」，user 给地块、NPC 状态、命中的记忆、本地事实段、最近 6 轮与玩家原话；参数与闲聊一致（`JsonOutput=false`、`Thinking=false`、`Temperature=0.8`、`MaxTokens=200`，1–3 句）。事实由本地生成：`QueryFacts.Build` 调 `LocalIntentParser.QueryReply` 得到事实串（地块、工步、体力、命中的记忆；「你在干什么」的工单分支现在也带体力），这串既是提示词里的唯一依据，也是回退台词。模型的措辞还要过 `QueryFacts.Accepts`：事实串里的地块、工步与体力必须还在，不能出现事实与命中的记忆里没有的地块（含「A9」这种不存在的 id）或「第 N 天」，问往事时还必须仍引用被引用的那条记忆（`LocalIntentParser.BestPlayerMemory`，优先玩家当时的原话）的地块或游戏日；不合格按不可用处理，空响应与 JSON 冒充台词一样重试一次，仍不合格就回退事实串并把 `IntentResult.UsedFallback` 置真，不把改过的答案交给玩家。`QueryReply` 与 `Accepts` 读同一次 `RecallForAnswer` 的命中，所以回答与决策可视化展示的是同一次检索；引用哪一条仍按 #7 的规则优先玩家原话（`BestPlayerMemory`），因此只有玩家原话排第 1 项时回答才字面等于第 1 项——#20 的验收场景（先下浇水令、跨日再问）正是这种情形，`QueryTests.记忆追问沿用记忆里的地块与游戏日_并与决策可视化第1项一致` 断言了它；第 1 项是别的记忆时，`IntentRouterTests.记忆追问优先引用玩家的话而不是自己的动作` 断言回答引用第 2 项。这是 #7「优先玩家原话」与 #20 验收口径的取舍：#7 的规则优先，回答仍限定在同一次检索的三条命中里。非请求句的追问 / 闲聊出口也以 `LocalIntentParser.Parse` 为准：模型把「你在干什么」判成 chat 时同标 `Correction` 并被纠正成追问，否则回答没有事实注入、还会把话写回记忆。离线或分类降级时同样直接给事实串（`Client` 为 null、预算为 0）。被本地纠正成追问的那一次始终标 `Correction` 并保留分类调用的模型名、耗时与 token（ADR-0004）——表达层成功、失败或回退事实串都不覆盖这个标记。测试：`QueryTests` 断言第二次请求的参数与提示词（口吻、系统规则、本地事实、状态、记忆、最近 6 轮、玩家原话在末尾）、改掉地块 / 游戏日 / 丢掉体力 / 编出不存在的 id 时回退事实串、「上次你让我浇的是哪块」与决策可视化第 1 项一致、空响应与 JSON 重试后回退、分类失败后仍试一次表达层、判成闲聊仍按追问回答且不写记忆、判成农活与表达层失败时仍标 `Correction` 并保留 token；`IntentRouterTests` 的向量检索与超时用例改成假模型分两次应答。HUD 的「本地模板」标记仍按 #19 只画在闲聊上。

**范围注记（#21 工单占位）**。接单即占住整块地：`FarmWorld` 多一张「地块 → NPC」登记表（`ClaimOf` / `FieldClaims` 只读），`TryAssignWorkOrder` 登记工单时同时占位，同一块地已被别人占着时返回「阿禾正在弄这块地」。占位优先于地块状态：`ActionValidator` 先答「这块地不归你」，再答「这一步此刻做不了」，所以效用打分里被占的地块不给有效候选，绕过派单直接执行也被同一句话拒绝。释放时机：工单完成、被取消（`TryCancelWorkOrder`；按钮与「别干了」这类意图留给 #22）、被拒绝且无法继续（能等的只有 `Field` 的四个「等条件」理由与「正在休息」，其余拒绝一律视为做不下去）、超过一个游戏日没有进展（`SettleDay` 里 `day - LastProgressDay > 1` 自动放弃）。两条边界：NPC 去休息不释放占位，休息期间也不算停滞；在自己的地块上做成任何工步（含插做的维护）都算进展，否则 3–7 天的长周期工单会被兜底规则误伤。决策抽屉在 ③ 里加一行「地块归属」，仍按 `ALIGNMENT.md` §四只呈现五项（ADR-0006）。测试仍只打 `FarmWorld`：`WorkOrderTests` 新增七条——占位与带名字的拒绝、完成释放、取消释放、换地接单释放旧占位、休息保留、无进展放弃、做不下去立刻释放；`FixedScenarios` 的「等条件」清单改为直接调 `ActionValidator.IsWaiting`，免得剧本在工单被放弃时挂在「没有登记工单」上。

## Testing Decisions

**好测试的标准**：只断言外部可观察行为，不断言内部实现。例如断言「不浇水的地块在十个游戏日后仍未成熟」，而不是断言某个私有字段的数值；断言「三本账满足入账减出账等于持有」，而不是断言某个字典的内容。

**接缝**：两个，均在测试中替换。

1. **`FarmWorld`** —— 最高的那条缝。五个工步的迁移、游戏日推进、背包守恒、效用打分的排序、记忆检索的加权，全部在这一条缝上测。UI 与表现层不参与测试。
2. **`IModelClient`** —— 外部 IO 的唯一出口。所有测试使用假实现，返回预置的分类结果与固定向量，因此测试不联网、不花钱、结果可重复。

不为 `MemoryStore`、`UtilityScorer`、`ActionValidator` 单开接缝：它们是 `FarmWorld` 内部模块，通过 `FarmWorld` 的行为暴露出来。`SecretFileLocator` 是 #4 的唯一例外（见「范围注记（#4）」）：它只做密钥来源决策，不碰领域状态。

`CropStages`、`CameraRig`、`PixelArt`、`PortraitFace`、`FarmLayout`、`SortingOrder`、`OverheadEmotes`、`FarmStartup`、`DialogueBook` 是 #12–#18 的表现层例外（见「范围注记（#11–#16）」与「范围注记（#18）」）：它们只把领域快照翻译成图集格位、机位、布局、表情或每名 NPC 的对话状态，不持有领域状态，也不依赖场景；场景渲染、Tilemap 拼接、HUD 布局与动画播放仍以 Play Mode 截图为准。`AssetLayoutTests` 是 #16 的交付护栏，只检查打包目录里没有 3D 模型/材质，不加载贴图。

`DialogueContext`（口吻 + 最近几轮）是 `IntentRouter` 的一个入参值，不另开接缝：表达层的提示词与降级仍在 `IntentRouter` + 假 `IModelClient` 这条既有例外缝上断言。口吻数据 `NpcTones` 是演示层文案，不是模块；测试只断言它进了 system 提示词、三人两两不同（见「范围注记（#19）」）。

`QueryFacts`（追问事实串与措辞校验）同样不单开接缝：它是 `IntentRouter` 内部的一个值类型，事实注入、改掉事实作废与回退都在 `IntentRouter` + 假 `IModelClient` 这条既有例外缝上断言（见「范围注记（#20）」）。

**测试的模块**：`FarmWorld`（含其内部的时钟、账本、打分、校验、记忆），以及 `IntentRouter` 的三出口分流与追问的事实注入。

**先例**：`prototype/field-state-machine` 分支上已有 `FieldTests`、`FarmLedgerTests`、`FarmClockTests` 三组 EditMode 测试，编码了「五步迁移」「不守恒即失败」「跨日事件次数」等断言，可直接迁移进正式实现。该分支同时证明了状态机可以编译并可被测试框架发现。

**运行方式**：`unity test --mode EditMode` 在无 GUI 环境下自带 batch 执行并输出 XML 报告，不依赖图形设备与桌面状态。

## Out of Scope

- 经济平衡与数值调优（题目明确说明不作为考察重点）
- 玩家手动种地
- 让闲聊或追问改变游戏状态
- 多人、联网存档、手工存档系统
- 多平台构建（仅 Windows Standalone）
- 生成式表情图像（表情为图标与文字气泡）
- 语音输入

## Further Notes

**设计依据**：`ALIGNMENT.md` 记录了全部 29 条对齐结论；`GLOSSARY.md` 固定了「工步」与「动作」等易混词；`docs/adr/` 记录了三条难以回退的决策；`docs/research/` 有三份一手来源调研（幻兽帕鲁的工作系统、斯坦福 AI 小镇的架构与 2026 年现状、DeepSeek 与硅基流动的接入参数与陷阱）。

**一路关键发现**：题目里的「施肥」「除草」在《幻兽帕鲁》中并不存在对应的工作类型，作物只经历空地到采集的四个阶段。因此本题的五步流程是农场模拟的流程套了帕鲁的皮，不必复刻帕鲁，按农场模拟设计即可。

**另一条关键判断**：帕鲁的自动化并非由语言模型驱动，而该开发商公开表示不做生成式 AI。出题人用一个不用 AI 的游戏命名了一道 AI 题 —— 那个「AI」正是要求实现者加进去的部分。

**原型**：`prototype/field-state-machine` 分支保留了状态机、时钟与账本的实现及测试，作为一手资料，不并入主干。

**已知不确定**：模型的实际延迟是否稳定落在 2–6 秒区间尚未验证，若超出则依赖降级层；素材下载的可行性在实现开始后才验证，失败时回退纯体块。
