## Problem Statement

演示已经能玩：一句话下指令，三名 NPC 把五步农活干完，决策可视化能把"想起了什么、想干什么、为什么否决"摊开。但打开包的第一眼是"粗糙"：

1. **场景假**。地面是一整块单色平面，天空是引擎默认渐变，草地的边缘直接露出来；房子、树、地块之间的比例像占位。
2. **HUD 像调试工具**。四块灰底面板压在画面上，占掉一半以上宽度，字号统一、没有层级，玩家要的信息和观察者要的信息混在一层。
3. **因此不接受"这只是一个功能演示"**。面试官看的是"这个人能不能做出一个像样的东西"，而现在这一版看起来像没做完。

## Solution

把表现层整体换成 2D 像素瓦片农场，HUD 换成羊皮纸风格的游戏 HUD：

- **画面**：俯视 3× 的瓦片农场——农舍在东、鸡舍在南、三块地并排、一条土路把人和地串起来；作物按五阶段换图；NPC 用四方向行走图。跟拍机位换成 4× 跟随特写。
- **HUD**：常驻只剩四件——顶部一条（第几天 / 当天进度 / 倍速）、左上三人卡（头像 + 体力 + 当前意图）、左下背包条、底部对话框（128 头像 + 名字 + 台词 + 例句 + 输入）。决策可视化退到 `Tab` 召唤的右侧抽屉。
- **反馈**：NPC 按事件在头顶冒一个像素表情（接单、被拒、去休息、转述），对话框随时显示说话的人是谁。

验收锚点是两张合成图：`TestResults/ui-art/farm2d_hud.png`（整屏）与 `hud_layer.png`（透明 HUD 层）。

## User Stories

1. 作为玩家，我想第一眼看到一个像游戏的农场，而不是一个 3D 技术演示，以便我愿意继续看下去。
2. 作为玩家，我想在俯视视角同时看到三块地和三名 NPC，以便观察谁在干活、谁在偷懒。
3. 作为玩家，我想一眼看出三块地分别处在哪个生长阶段，以便知道哪块该浇水、哪块该收。
4. 作为玩家，我想看到作物从播种到成熟的五种外观，以便不用看数字就判断进度。
5. 作为玩家，我想看到 NPC 朝行走方向转身并有行走动画，以便动作不像贴图在滑。
6. 作为玩家，我想在跟拍视角看清一个 NPC 的动作细节，以便验证它真的在干那件事。
7. 作为玩家，我想随时在俯视与跟拍之间切换，以便从"看全局"切到"看细节"。
8. 作为玩家，我想看到当前是第几天、今天过了多少、时间几倍速，以便理解节奏。
9. 作为玩家，我想看到种子库和产出仓里有几个、是什么，以便知道还能种多少、收了多少。
10. 作为玩家，我想在对话框里看到说话人的头像和名字，以便知道这句话是谁说的。
11. 作为玩家，我想按回车就把话发出去，并且上一句、NPC 的回应和输入框在同一个框里，以便眼睛不用在屏幕上下跑。
12. 作为玩家，我想点一个例句就能试一条指令，以便不用猜这个 demo 能听懂什么。
13. 作为观察者，我想按 `Tab` 打开决策可视化，以便在需要证据时把它调出来、不需要时别挡着农场。
14. 作为观察者，我想在决策可视化里继续看到五项（记忆、意图、候选与否决原因、最近一次模型调用、状态条），以便确认它没有为了好看而丢掉证据。
15. 作为观察者，我想看到 NPC 头顶冒出表示"接单 / 被拒 / 去休息 / 转述"的像素表情，以便不点面板也知道发生了什么。
16. 作为观察者，我想在三人卡上看到每名 NPC 的体力条和一句当前意图，以便对比三个人的状态差异。
17. 作为面试官，我想在模型不可用时看到一个照常运转的 demo，以便判断降级是不是真的。
18. 作为面试官，我想关掉素材回到体块版本，以便确认领域逻辑并不依赖美术资源。
19. 作为面试官，我想看到回归报告仍然全绿，以便确认换皮没有碰到领域逻辑。
20. 作为维护者，我想让域层代码一行都不用改，以便这次重写只承担表现层的风险。

## Implementation Decisions

**画面规格**。正交相机，像素单位 16px/格。俯视 3×（一格 48px，一屏约 26×15 格），跟拍 4×（一格 64px，约 20×11 格）。俯视必须装下三块地与三名 NPC，这是它存在的理由；4× 只用于跟拍。相机不做自由平移，避免多一套输入。

**场景装配**。地面与土路用运行时生成的 Tilemap；建筑、树、作物与 NPC 用 SpriteRenderer，深度排序按 Y（Transparency Sort 设成自定义轴）。场景仍由代码搭建，不引入 prefab 装配层——这是 #2 以来的既有约定。

**角色**。四方向行走图，16×32 一帧，每方向四帧；朝向取速度的主分量，停下回到该方向第一帧。行走速度仍是表现层参数，不进人设。

**作物**。沿用 `CropStages` 的五阶段划分，只把"进度 → 阶段序号"的产物换成图集的行列：萝卜用带果实的行，小麦用金黄的那行，成熟那一格即成品外观。

**资产**。只提交用到的十来张图（三张头像、三张行走图、作物图集、室外瓦片、建筑、物品图标、表情、树），放在资源目录下按用途分文件夹；其余留在仓库外，不进包。素材是原作游戏图集，仓库保持私有、仅作演示，不外分发——这条写进 README 的素材与许可段落。

**HUD**。羊皮纸底色 + 深褐描边；字号只留三档（标题 18 / 正文 15 / 备注 12）；间距按 8px 网格。常驻四件（顶部条、三人卡、背包条、对话框），决策可视化是 `Tab` 召唤的右侧抽屉（宽 420，左侧留一条农场）。头像按 64→128 的两倍整数放大，表情按 16→32；不做非整数缩放。

**肖像与表情**。阿禾用 Robin、阿芽用 Haley、阿土用 Gus 的头像与行走图。表情是六档语义（平常、笑、得意、不耐烦、懵、累），由"出口 + 状态"决定，写成纯函数；头顶表情只在一组事件发生时冒 2.5 秒（接单、被拒、去休息、转述），NPC 出屏或相机背后不画。

**回退**。「素材开/关」保留，语义变成"像素素材 / 体块"；贴图缺失时回退体块或跳过装饰，不抛异常——与 #9 建立的"素材缺失是常规路径"一致。UI 素材不受这个开关影响。

**分层**。域层（`FarmWorld`、效用打分、动作校验、记忆、意图路由）一行不改；表现层只读它的快照。这是本次重写唯一的止损点，也是敢动的理由。

**分支**。2D 在 `feature/2d-presentation` 上做，`main` 保持现在的 3D 可交付版本，验收通过再合。

## Testing Decisions

**好测试的标准**：只断言外部可观察行为，不断言内部实现，也不打开场景。例如断言"缺水的地块十个游戏日后仍未成熟"，而不是断言某张贴图被加载过。

**接缝**（全部是纯函数，EditMode 直接调用）：

1. `FarmWorld` —— 既有接缝，本次不动，132 条断言里绝大多数还打在它上面。
2. `CropStages` —— 既有接缝，只把"阶段 → 图集格位"补进来，五阶段划分不变。
3. `CameraRig` —— 契约从"3D 机位姿态"改成"档位与观察中心"：俯视固定 3×，跟拍锁定某名 NPC 并切到 4×，未知 id 不改档位。
4. `PixelArt` —— 新增，替代 `QuaterniusArt`：按名字取图并切格，缺失返回 null；切格结果（行、列、尺寸）可断言。
5. `PortraitFace` —— 新增：出口与状态映射到六档表情，纯函数。
6. `FarmLayout` —— 新增：地块、NPC 起点、产出仓与休息点在瓦片网格上的坐标，断言数量、两两不重叠、都在可走范围内。

**删除或重写**：`QuaterniusArtTests`、`UrpMaterialTests`、`ArtMaterialTests` 删除（它们断言的是已退出的管线）；`CameraRigTests` 按新契约重写；`CropStageTests` 保留"五阶段两两可区分"，去掉颜色/尺寸那几条，改成断言格位不重复。

**不测**：渲染结果、Tilemap 拼接、HUD 像素级布局、动画播放——这些用 Play Mode 截图验收，与 #9 的口径一致。

## Out of Scope

- 寻路与避障（NPC 继续直线移动）
- 动物、天气、季节切换
- 存档、音效、语音
- 2D 物理
- 多张地图或可探索区域
- 删除 3D 版本（留在 `main` 与分支上）
- 录屏、压测与干净机器验收（#10，排在本轮之后）

## Further Notes

**锚点**：`TestResults/ui-art/farm2d_hud.png` 是整屏目标，`hud_layer.png` 是可直接叠在实现截图上的 HUD 层；两张都在不入库的 `TestResults/`，需要长期保留时挪进 `docs/images/`。

**为什么不是 3D**：见 ADR-0005。核心是通用 CC0 低模的天花板，以及"地面 / 天空 / 露边"这三件换任何包都要自己做的事。

**素材约束**：原作游戏图集，仓库私有、仅作演示；README 的「素材与许可」要改成"CC0 3D 旧素材 + 星露谷原画（演示用）"并列，不能把 CC0 的结论套到后者身上。

**规模**：表现层约 1,700 行里六成重写，域层零改动，测试约 10 条新增、12 条删除或重写。
