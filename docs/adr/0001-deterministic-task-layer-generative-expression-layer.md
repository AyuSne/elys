# 任务层确定性、表达层生成式

题目同时要求两件事：种田全流程必须跑通（步骤完整、时间与背包正确），而 NPC 的表现必须像 AI 小镇那样自然。这两件事对「可靠性」的要求完全相反，所以拆成两层：**排程与执行是确定性的**（效用打分 + 动作队列），**语言与表情是生成式的**（LLM）。LLM 只做两件事——把玩家的自然语言解析成意图、把 NPC 的状态渲染成台词与表情——**永远不允许它直接修改游戏状态**。所有 LLM 产出的动作都要经过白名单与前置条件校验，校验失败就回退到默认动作。

这样拆分让「全流程正确」成为可测试的属性（EditMode 测试覆盖五步迁移与背包收支守恒），同时把生成式的不确定性限制在不会破坏正确性的那一层。

**考虑过的选项**：用一个 LLM agent 同时负责排程与表达。否决原因：不可回归测试、行为会漂移、每一步都要等模型返回因而无法满足延迟要求，且失败时整个 demo 会卡死而不是降级。

**后果**：NPC 的「自主性」上限被动作集的大小约束——它只能在白名单内表现聪明。这是有意的取舍，换来的是可演示、可复现、可自证。
