# 工单占位：一块地同一时刻只属于一名 NPC

试玩里阿禾与阿土同时「前往 A3 · 施肥」，另一次是两人同时「前往 A2 · 播种」（#17 缺陷 3）。原因不在效用打分，而在它之上少了一层：`RankCandidates` 每人各算各的，同一块地对所有人都是有效候选，派单也不登记「谁已经在弄这块地」。玩家听到「好嘞」却看到另一个人先动手，「接单是承诺」这条体验就不成立。

这一票把**占位**做成领域状态：`FarmWorld` 在接单时把整块地记到那名 NPC 名下，同一时刻一块地只属于一张工单。别人再对这块地下令，得到一句带名字的拒绝「阿禾正在弄这块地」；效用打分里这块地不再给出有效候选，绕过派单直接执行也要过同一道动作校验。释放时机四种：工单完成、被取消、被拒绝且无法继续（种子耗尽、地块状态已经变了）、超过一个游戏日没有进展。**NPC 去休息不释放**——休息有界、会自己结束，回来还能接着干。

占位粒度是**整块地**，不是单个工步。同一块地的工步有先后依赖（播完才能浇），拆到工步会让两名 NPC 在同一块地上一人浇水一人施肥，看起来仍然像抢；「等成熟」期间插做的维护步也会和别人的计划步互相打断。

占位与「每个工步执行前重新校验」不冲突，是两层：占位管「谁能接这块地」，动作校验管「这一步此刻做不做得了」。工单仍然每个工步都过 `ActionValidator`，只是占位先于地块状态回答「这块地不归你」。兜底规则（超过一个游戏日没有进展自动放弃）是这一票的已知代价：判据是 `SettleDay` 里 `day - LastProgressDay > 1`，「有进展」= 在自己的地块上做成过任何一步（计划工步或插做的维护），所以跨过一个日界还留着、跨过两个才放弃。它保证没人推进的工单不会把地块锁死，代价是一张两天里一步都做不成的长周期工单会被放弃（例如刚做完四步、作物还差几天成熟，维护需求又都低于阈值的那两天）——这是「卡住一个游戏日自动放弃」这条规格本身带来的，要放宽得先改规格。被放弃的工单目前在画面上表现为意图消失，需要 #23 的工单三态把它说成「放弃」而不是静默丢掉。

**考虑过的选项**：

1. 只在每个工步执行前重校验，不登记占位。否决原因：两名 NPC 会同时挑中同一块地，一个人做完、另一个人被拒；玩家永远听不到「被别人占着」，只会看到自己的工单莫名其妙不动，接单仍然不是承诺。
2. 占位到工步粒度。否决原因：同一块地的工步有先后依赖，分开占位等于让两个人同时在这块地上做不同的事，与「接单即占住整块地」的体验相反；维护步与计划步还会互相拆台。
3. 玩家下令只排进队列，由负责的 NPC 自己抢活。否决原因：这正是缺陷 3 的现状；玩家拿不到「谁在弄、我该等还是换一块」这句话。

**后果**：`FarmWorld` 多一张「地块 → NPC」登记表与 `ClaimOf` / `FieldClaims` 两条只读查询，`ActionValidator` 多一条优先于地块状态的占位校验，`WorkOrder` 多一个「最近一次有进展的游戏日」。决策抽屉在 ③ 候选与否决原因下面加一行「地块归属」，读的是同一份占位，不新增第 6 项。固定剧本的证据文本不变（三条剧本都只指挥一个人，占位不改变它们的结局），`ScenarioTests` 的三次逐字一致仍是这条改动的回归护栏。释放时机里的「被取消」只做到领域能力 `TryCancelWorkOrder`：按钮与「别干了」这类取消意图留给 #22，否则这一条释放时机没法测试。
