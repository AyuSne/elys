# 用效用打分而非 GOAP 做任务分配

NPC 决定「现在去做哪件农活」用一张手写的效用打分表，不引入 GOAP 规划器。原因是这道题里农活的**顺序几乎固定**（播种 → 浇水 → 等待生长 → 收获），真正的决策只有两个：**谁来做**、**现在做哪件**。效用打分正好覆盖这两点：按干湿度、杂草、成熟度、距离、体力加权排序即可。

**考虑过的选项**：[ReGoap](https://github.com/luxkun/ReGoap)（1.1k★，Apache-2.0，仍在维护）。它适合「目标不固定、需要搜索动作序列」的场景，而这里的动作序列是已知的，规划搜索属于过度设计。

**后果**：若后续要支持需要多步组合才能达成的目标（例如「修一条水渠再引水」），当前结构撑不住，需要重新引入规划层。这个概率在 7 天版本里被认为很低。
