# 出口判定以玩家原话为准

三个出口（农事指令、追问、闲聊）的分类过去完全交给模型。问题是模型会犯错，而且玩家的话术可以诱导它：一句纯闲聊被分类成农事指令，会凭空改地块；一句夹带请求的闲聊被分类成闲聊，NPC 就假装没听见；让人「忽略上面的规则」时，更没有任何本地规则兜底。

这一票把出口的最终裁决权收回到本地：`LocalIntentParser.IsFarmRequest` 用确定性规则判断玩家原话是不是农事请求（白名单动作词、祈使标记、非问句、非陈述往事、非否定），模型只负责在这句话确实是一个请求时提供目标、地块、品种与措辞。请求一定进入 `ActionValidator`；不是请求的话一定不能产生工单。模型的分类和本地判定不一致时，结果标记为 `Correction`，HUD 与决策可视化仍显示这次调用的模型名、耗时与 token。

这样「三个出口」从模型的软分类变成一条可测试的硬边界：闲聊与追问不可能改地块、时钟与背包，品种白名单也不可能被「闲聊」绕过。

**考虑过的选项**：

1. 完全信任模型返回的出口。否决原因：无法回归测试，提示注入可以把任何一句话变成任意操作。
2. 只用本地规则分类。否决原因：中文说法太多，本地关键词覆盖不了「随便种点什么」这类表达，而这正是模型擅长的部分。

**后果**：本地规则成为模型与游戏状态之间的第二道闸门。规则本身的误判（把请求当成陈述）表现为请求被忽略，而不是状态被改坏——失败方向是安全的；代价是个别口语化请求要靠模型的 `farm_command` 才被接受，纯本地降级模式下识别能力略降。演示层因此多了一个「本地出口校验接管」的调用状态，观察者能看出模型和本地规则谁说了算。
