## 一句话

题目把那两个名词并排放，但它们是**两套不重叠的技术栈**：帕鲁代表「确定性任务调度」，AI 小镇代表「记忆驱动的表达」。题目真正要的是**把两者缝起来**——种田必须是确定性的（保证流程/时间/背包正确），说话必须是生成式的（保证观察价值）。

## 一、「小帕鲁」是什么

**不是专有名词。** 检索不到任何官方产品、动画、手游或衍生作使用该名。

最可能的读法是语义叠加：

1. 「小 X」是中文对萌系生物的常规爱称；
2. 「帕鲁」在 2024 年初已脱离游戏，变成「被压榨的劳动者」的通用梗（「你不干，有的是帕鲁干」）；
3. 这个梗不是纯粹的外部附会——游戏内**真有一个叫「社畜」（Work Slave）的被动技能**，官方把自嘲写进了数值。

代入原题：「像帕鲁那样的小家伙替我把农活全干了」，语义通顺。铺底读法还有「体型小的帕鲁」（攻略分类词）和「某部衍生作的误记」（最接近的是农场向《Palworld: Palfarm》，官方文案几乎逐字对应题目，但没有任何材料称它「小帕鲁」）。

**面试表述建议**：说「类似 Palworld 里在基地自动务农的帕鲁」，别假设它是某部作品的名字。

## 二、帕鲁的自动化：不是 LLM，是效用调度

| 项 | 实际 |
|---|---|
| 工作类型 | **12 类**：Kindling / Watering / Planting / Generating Electricity / Handiwork / Gathering / Lumbering / Mining / Medicine Production / Cooling / Transporting / Farming |
| 等级 | 自然 1–8，Pal Essence Condenser 可升，**上限 10**；设施可要求最低等级，不达标不干活 |
| 玩家控制 | 三层：允许/禁止某类工作、工作强度档位、把某只永久固定到某设施（Monitoring Stand） |
| 自主部分 | 其余靠帕鲁自己找活做，底层有一张**官方调参、玩家不可编辑的优先级表**，算法**未公开** |
| 状态 | Health / Hunger / Sanity(SAN) 三条；SAN 触底 → 频繁拒工 → 疾病 → 最极端 `Troublemaker`（工作 −50、移动 −50） |
| 人格 | 0–4 个被动槽，`Work Slave` / `Slacker` / `Workaholic` 直接改写劳动表现 |

**没有任何官方或社区材料表明帕鲁由 LLM 驱动。** 反而 Pocketpair 公开表态不做生成式 AI。这是个值得在面试里点出来的反差：**出题人拿一个不用 AI 的游戏，来命名一道 AI 题**——那个 "AI" 是要求你加进去的，不是帕鲁自带的。

### 题目的一个事实性缝隙

帕鲁里**没有「施肥」和「除草」这两种工作类型**。作物只经历「空地 → 已播种 → 生长 → 成熟 → 被采集」；题目的「收获」对应的是 `Gathering`，不是独立的 Harvesting。

也就是说，题目那五步是**农场模拟（星露谷式）的流程，套了帕鲁的皮**。

这对你是好消息：**不必复刻帕鲁，按农场模拟设计即可**，但要能说清为什么这么做——因为出题人真正在意的不是帕鲁的机制，而是「AI NPC 自主跑完一串工步」这件事本身。

### 帕鲁给出的三条可用启发

1. **指令被降解为「许可 + 指派」**。玩家从不说「去给那块地浇水」，而是建灌溉设施、允许 Watering、派一只有 Watering 的帕鲁。LLM 只需把「把这片田种满小麦」翻成 `{work_type: planting, target: 3号田, until: 满}`，剩下的发现、排队、寻路、抢占交给确定性层。
2. **智能在环境里，不在 NPC 里**。地块本身就是状态机，它在广播需求；帕鲁只是「能对某状态施加某动作」的执行器。天然支持并发、中断、存档。
3. **「自然」来自可归因，而非台词量**。头顶的饥饿图标、面板上的「SAN 低 / 生病 / 怠工」、一句 "Extremely unhealthy due to neglect"——玩家随时能回答「它为什么停下」，行为才变成故事。这正是「表情包输出」该有的形态：**状态 → 图标 / 气泡 / 短句**。

## 三、斯坦福 AI 小镇：记忆架构，不是聊天

- 源头：Park et al., *Generative Agents*, UIST 2023（[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)），25 个 agent 在 Smallville 生活两天。
- 四模块：**memory stream**（每条含描述、时间戳、`poignancy` 1–10、embedding）→ **retrieval**（`recency` 0.995 指数衰减 + `importance` + `relevance`，三项归一化后等权相加）→ **reflection**（importance 累计 150 触发，最近 100 条 → 3 个问题 → 5 条带证据的 insight）→ **planning**（5–8 条日计划递归分解到小时、再到 5–15 分钟）。
- 评估是**访谈式可信度**，不是任务成功率：100 名评估者排序，完整架构 TrueSkill 29.89，全消融 21.21。
- 成本：25 agents × 2 天「数千美元 token 费、数天机时」。
- 官方仓库停在 2023-08-11，锁死 `openai==0.27.0` / Django 2.2，**不能直接跑**；a16z 的 AI Town 反而仍维护，是更好的工程参考。

## 四、2024–2026 的现状（面试时的加分项）

- **1,052 人个体模拟**（[arXiv:2411.10109](https://arxiv.org/abs/2411.10109)）：用访谈/问卷建 agent，在留出题上达到本人两周重测一致性的 83%/82%/86%，人口基线 74%。
- **系统映射研究**（[arXiv:2611.05427](https://arxiv.org/abs/2611.05427)，2026-11 投稿，已被 IEEE Trans. Games 接收）：377 篇筛 42 篇。短期记忆 60%、世界状态 grounding 69% 已近普遍，但**长期记忆仅 31%、reflection 38%、RAG 14%**；响应时间 **2.6–15 秒**。
  → 这条最有说服力：**做出长期记忆本身就是少数派**。
- **结构化 + 合法性校验是标配**：只把合法动作给模型、执行前二次校验，比换更大的模型更有效（Agenerela 的实测，Unity 专属项目，注册式动作约束）。
- **延迟是体验问题**：[Entertainment Computing 2026 的实证研究](https://doi.org/10.1016/j.entcom.2026.101213)表明 token 延迟会改变玩家对 NPC 社交性的感知。
- 商用侧：NVIDIA ACE 主推端侧 SLM + Game Agent SDK（**无 Unity 官方插件**），Convai 有 Unity 插件，Inworld 转向推理服务。

## 五、落到这道题：保留什么、砍什么

**必须保留**

1. 人设 + 状态卡（性格/体力/心情/天气/田块状态），每次决策注入——没有状态就只是聊天机器人。
2. memory stream + importance 检索——「记得你浇过水」和「把 A 的秘密告诉 B」的唯一来源。
3. 粗粒度计划 + 动作队列 + 重规划：一天 5–8 个 beat，LLM 只在 beat 级决策。
4. 结构化动作 + 白名单校验 + 回退：`{action, target, duration, speech, emote}`；**不让 LLM 直接改 Unity 状态**。
5. 双层延迟：即时层模板/小模型出短 bark + 表情，异步层出完整对话与计划。
6. 可观察层：气泡、表情、内心独白、关系图、日记、跟随镜头。

**砍掉**

- 全天逐小时 + 5–15 分钟的递归 LLM 分解（一个 agent 一天几十次调用，多数动作玩家看不到，还越分解越漂）。
- 每 tick 对每个 agent 做感知 → LLM 反应（O(N²) 调用），改为事件驱动。
- 25 个 agent——5–8 个有区分度的人设比 25 个模板人更有观察价值。
- 完整反思树 + 证据引用，保留「每天结束 1 次反思、产 2–3 条 insight」即可。

**题目第 4 条已明说数值不是重点**，别去做经济平衡表。
